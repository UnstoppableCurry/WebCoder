问题陈述（来自 README 与源码职责注释）

README 列出的目标能力包括：在 Web 终端里实时交互、针对移动端的界面、多用户认证授权、会话与项目隔离、文件浏览与编辑、邮件通知，以及「智能管家」式的任务推进与状态监控。

源码把系统拆成两层：

  • src/core.py：内部能力层，默认端口 3001。注释写明职责是 PTY 进程创建/停止/重启、WebSocket 终端、项目目录、输出缓冲、webhook 回调。
  • src/gateway.py：对外业务层，默认端口 3000。注释写明职责是 Web UI、邮件、管家、状态与业务逻辑、带认证的 WebSocket 代理、接收 Core webhook、代理系统管理。

因此，要使用产品本身，需要在本机或服务器上同时运行这两个 Python 进程（见 scripts/start.sh 与 docker/entrypoint.sh），而不是打开本静态站点。

为什么这里没有「在线试用」

登录页、主应用页、管理后台均由 Gateway 的 HTMLResponse 函数返回（路由 /、/app、/admin）。终端依赖 xterm 静态资源与 /ws/{project_name} 代理到 Core。Pages 只能托管静态文件，无法提供 PTY、SQLite 初始化或 AI CLI 子进程。

本站也没有产品截图：仓库中不存在经过核实的界面截图资源，页面不会用占位图冒充运行效果。

与 README 功能列表对应的源码位置

README 表述仓库中可见的实现位置
多 AI 提供商（Claude、Kimi、Codex）src/config.py 的 PROVIDER_CONFIGS 为三个名字配置了 CLI 命令与环境变量；src/core.py 按 provider 执行对应命令。注释写「支持 Claude, Kimi」；Codex 出现在配置表中。管家侧另有 DeepSeek HTTP 调用（src/services/deepseek_service.py）。
Web 终端 / WebSocketCore 与 Gateway 均有 WebSocket；Gateway /ws/{project_name} 代理到 Core，前端页面引用 static/xterm.min.js。
多用户 / JWTsrc/auth/、src/api/auth.py；JWT 默认密钥在配置中为 change-me-in-production。
智能管家 / 任务推进src/agents/supervisor.py、project_agent.py、butler_agent.py 与 src/api/butler.py。
邮件通知src/services/email_service.py；安装文档给出 EMAIL_ENABLED 等变量（这些名字在 config.py 当前文件中未见定义，见局限页）。
文件管理src/api/files.py 提供列出、读写、上传下载与部分 Git 接口。
