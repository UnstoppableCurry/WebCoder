证据边界

能说清的限制，不补未证实的故事

CHANGELOG 仍有「Unreleased」与日期为 2024-XX-XX 的 1.0.0 节。本站不把该文件当作已发布版本证明。

GitHub Pages 跑不了产品

  • UI 在 gateway.py 的 Python 字符串里，不是独立前端构建产物。
  • 终端需要 Core 的 PTY 子进程与双向 WebSocket。
  • 数据库初始化依赖 DATABASE_PATH（见下一节）和 SQL 迁移。

src/config.py 与其它模块的导入差

当前 config.py 定义了路径、端口、JWT_*、Claude/Kimi/Codex 密钥 URL、以及 DEFAULT_AI_PROVIDER / PROVIDER_CONFIGS。下列名字在其它文件中 from config import ...，但未出现在该配置文件正文中：

符号引用位置（示例）
AI_PROVIDERcore.py
DATABASE_PATHdatabase.py
CORE_WS_URLgateway.py
DEEPSEEK_API_KEY / DEEPSEEK_BASE_URL / DEEPSEEK_MODELdeepseek_service.py, butler_agent.py
EMAIL_ENABLED 及 SMTP 相关email_service.py；安装文档也列出
AGENT_HEARTBEAT_INTERVALproject_agent.py
DEFAULT_AUTH_DAYSauth.py, admin.py
VERIFICATION_CODE_EXPIRE_MINUTEScrud.py

按现状，这些导入在解释器加载对应模块时会失败，除非另有未纳入本仓库的配置层。这是阅读源码得到的限制，不是性能结论。

文档引用了、仓库里没有的文件

  • README：docs/configuration.md、docs/api.md
  • installation：.env.example、requirements-dev.txt、scripts/start-dev.sh、usage.md
  • deployment：scripts/backup.sh、systemd unit 文件、完整 k8s 清单、Compose nginx 用的 docker/nginx.conf
  • 克隆 URL 普遍为 github.com/yourusername/webcoder
  • Dockerfile 创建 /var/lib/ai-code-platform/projects，配置默认项目根是 /var/lib/webcoder/projects
  • installation 验证 /api/health，Gateway 未见该路由

源码中写明、部署时需自行处理的默认项

  • JWT_SECRET_KEY 默认 change-me-in-production
  • 默认管理员 admin / admin123
  • Gateway 与 Core 的 CORS allow_origins=["*"]
  • 创建进程默认 skip_permissions=True，会带上各 CLI 的跳过权限参数

文档中的防火墙、Fail2Ban、Let's Encrypt 只是 Markdown 步骤，仓库没有对应的自动化验收。

提供商：配置存在 ≠ 本站验证过

PROVIDER_CONFIGS 键为 claude、kimi、codex。Core 对 Kimi 会话目录有专门分支，对 Claude 有空的参数分支；没有对 Codex 的对等会话逻辑注释。管家与阶段分析走 DeepSeek，但 config.py 未定义 DeepSeek 变量。本站不宣称任一提供商已在生产环境或本 CI 中跑通。

README 功能列表中的「移动优先」「安全可靠」等形容词，这里只当作项目自述，没有独立评测数据。
