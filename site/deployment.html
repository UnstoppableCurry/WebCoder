部署教程（按文档，非背书）

文档列出三种方式：Docker Compose（文中写「推荐」）、systemd 双服务、以及一份单副本的 Kubernetes YAML 示例。

方式一：Docker Compose

文档假设 Ubuntu 22.04，安装 docker.io、docker-compose、git，将用户加入 docker 组。然后克隆占位仓库、复制 .env、docker-compose up -d。

Nginx 示例监听 80，反代 http://localhost:3000，并设置 WebSocket 相关头与 proxy_read_timeout 86400。SSL 示例使用 certbot。

仓库中的 Compose 文件还把数据卷挂到 /var/lib/webcoder 与 /root/.webcoder，并把主机 ./.env 只读挂进容器。Dockerfile 基础镜像为 python:3.11-slim，entrypoint 启动两个 Python 进程。

方式二：systemd

文档给出两个 unit：ai-code-core.service 执行 venv/bin/python src/core.py；ai-code-gateway.service 在 core 之后启动 src/gateway.py。工作目录示例为 /opt/webcoder，用户 ai-code。仓库中没有现成的这两个 service 文件，需要按文档自行放置。

方式三：Kubernetes 示例要点

文档 YAML 使用 replicas: 1，同一 Pod 内 core（3001）与 gateway（3000）两个容器，镜像名为占位 your-registry/webcoder:latest。Service 类型 LoadBalancer，端口 3000。密钥通过 secretKeyRef 名为 ai-code-secrets 的 kimi-api-key。仓库中没有配套的 k8s 清单文件，仅存在于 Markdown。

文档中的加固 / 监控 / 备份 / 更新

  • ufw：默认拒绝入站，放行 22/80/443。
  • 安装 fail2ban；logrotate 示例路径 /opt/webcoder/logs/*.log。
  • 监控：安装 prometheus-node-exporter，文中未给出完整告警规则文件。
  • 备份：复制 ~/.webcoder/ai_code_platform.db，打包 /var/lib/webcoder/projects，删除 30 天前文件。更新流程引用 ./scripts/backup.sh——该脚本当前不在仓库中。
  • 故障排查：systemctl status / journalctl、检查 3000/3001、htop 与磁盘。

Core 使用 os.fork 与 pty，文档系统列表以 Linux / macOS / WSL 为主；未提供原生 Windows 服务说明。
